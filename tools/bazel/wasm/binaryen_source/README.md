# Original Binaryen source SDK

The source SDK builds Binaryen 117 from its original `version_117` commit and
exact Googletest submodule. It preserves upstream tests, assertions and LLVM
DWARF support. A declared native compiler, CMake, Make, shell SDK and Python
execute the build. No ambient tool or compiler is discovered.

The rule exposes the generated executable and runtime through `NativeSdkInfo`,
plus original CMake compile commands, compiler dependency outputs and linker maps.
These are inputs to compiler-derived source attribution. They do not constitute a
complete selected-source or license provider. Production optimizer registration
requires original output parity, complete attribution and platform qualification.

The original archive contains the publisher LLVM license at
`third_party/llvm-project/include/llvm/LICENSE.TXT` and its scoped Support notice.
The original LLVM readme pins revision `6c86d6efaf129c42d37121f1e7e9a7adffb54c1a`;
the nested license is byte-identical to that revision's original publisher file.
The compiler-selected consumer must join those scopes and any retained MD5 or
Unicode-derived source terms separately. This factory does not expose complete
selected source attribution. Genuine native compilation, runtime and optimizer
output parity remain qualification requirements.

The `compiler_objects` and `compiler_archives` output groups retain original
same-build `.o` and `.a` bytes with build-relative member names. The existing
native retained-source collector uses those bytes to bind actual linker-map
archive members to their compiler actions; configured sources alone are never
selection authority. These output groups do not grant license completeness.

The original Unicode9 case-folding input is declared independently of compilation. Its original LLVM generator runs against the pinned original data without network acquisition inside the action. The complete generated source must equal the original LLVM publisher File. Two exact command-comment edits then bind that File to the original Binaryen archive member. The selected-source join retains the original data copyright, Unicode9 release readme, publisher terms and linked publisher license. Missing or changed inputs refuse the join. This closes that scoped source relationship; native compilation, complete compiler-source attribution and platform qualification remain required.

The original compiler configuration output captures the same build's retained inputs before its private source and object directories close. Each original Make dependency File is parsed independently by the shared linked-source collector; duplicate object facts refuse the join. Both the original executable and Darwin shared library use their actual native image and linker map. Original archive member hashes bind retained archive members to the same compiled objects. Selected Binaryen, Googletest and LLVM Files are partitioned by their exact original source roots, checked against original archive bytes, and joined to their scoped authentic notices. The existing original notice output contains those texts. Unknown compiler/SDK/generated inputs remain explicit pending facts; `complete_notices` refuses their admission. This action provides no complete SelectedAttributionInfo until those original origins and the native qualification are resolved.

The two original CMake-generated compiler inputs have an exact producing-source join. Selected `config.h` is reproduced from the original `config.h.in` and pinned project version. Selected `WasmIntrinsics.cpp` is reproduced by the original CMake prefix from the original template and `wasm-intrinsics.wat`. The same declared source-CMake executable replays those commands with a closed environment, and every generated byte must match the actual selected File. Their original template, data and CMake command Files then join the existing Binaryen source/license partition. Unselected generated inputs acquire no attribution. The exact executed source-CMake File stays in the existing pending-source boundary until its original implementation/license attribution joins; successful source reproduction grants no generator attribution. Compiler/SDK implementation origins also remain required for complete admission.
